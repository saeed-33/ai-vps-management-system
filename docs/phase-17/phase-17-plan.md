# خطة المرحلة السابعة عشرة: ربط السيرفرات الحقيقية وحفظ تقارير المراقبة

## الهدف

جعل دورة المراقبة قادرة على:

- استخدام إعدادات SSH المعرفة للسيرفر لجمع قياسات حقيقية.
- حفظ دورة المراقبة والتقارير والـ metrics في PostgreSQL عند توفر قاعدة البيانات.

## النطاق

- ربط دورة المراقبة بإعدادات SSH القادمة من إدارة السيرفرات.
- إضافة persistence اختياري لتقارير المراقبة.
- حفظ `monitoring_cycles`.
- حفظ `periodic_monitoring_reports`.
- حفظ `monitoring_metrics`.
- استخدام UUID مستقر لتحويل IDs النصية الحالية إلى UUIDs صالحة للجداول.
- إبقاء fallback إلى memory عند غياب قاعدة البيانات.
- توثيق خطوات التجربة مع سيرفر حقيقي.

## خارج النطاق

- تخزين دائم لإعدادات SSH نفسها.
- تشفير الأسرار.
- CRUD كامل للسيرفرات.
- تحليل المشكلات.
- تشغيل وكلاء متخصصين.
- حلول أو sandbox.

## متطلبات التجربة الحقيقية

- PostgreSQL يعمل.
- تطبيق migration `0001_initial_schema.sql`.
- `DATABASE_URL` مضبوط في `apps/api/.env`.
- إعداد SSH محفوظ من صفحة `/servers`.
- السيرفر يسمح بتنفيذ أدوات read-only.

## ملاحظة

إذا لم تكن قاعدة البيانات جاهزة، تستمر دورة المراقبة في إنتاج تقارير داخل الذاكرة فقط.
