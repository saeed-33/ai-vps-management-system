# بنية النظام

## نظرة عامة

يتكون النظام من لوحة إدارة ووكيل ذكي، لكن التنفيذ العملي يقسمهما إلى طبقات واضحة:

```text
Admin Panel
Backend API / Control Plane
MCP Gateway
Agent Orchestrator
Workers / Scheduler
Database / Vector Store / Object Storage
Sandbox
Telegram Adapter
```

## لوحة الإدارة

مسؤولة عن التحكم والعرض والتعريفات التشغيلية:

- إدارة المستخدمين.
- إدارة السيرفرات.
- إدارة التقارير.
- إدارة ملفات المراقبة.
- إدارة الوكلاء المتخصصين.
- إدارة الأخطاء والمشكلات.
- الإحصائيات.
- السجلات.
- إدارة صلاحيات الوكيل.
- واجهة محادثة.
- إدارة الحلول المسموح تنفيذها.
- إدارة أدوات التنفيذ المسموحة.
- إدارة الوثائق والروابط.

لوحة الإدارة لا تنفذ أوامر مباشرة على السيرفرات. لكنها تسمح بتعريف ما يلي:

- ملفات المراقبة.
- الوكلاء المتخصصون.
- الأدوات المسموحة لكل وكيل.
- شروط تشغيل الوكلاء المتخصصين.
- الحلول المسموحة وسياسات اختبارها.

## Backend API / Control Plane

هذه طبقة القرار المركزية:

- المصادقة والصلاحيات.
- إدارة البيانات.
- تطبيق سياسات التنفيذ.
- تسجيل audit logs.
- استقبال نتائج الوكيل.
- إدارة التقارير والمشكلات.
- إدارة الوثائق والفهرسة.
- إدارة تعريفات الوكلاء المتخصصين.
- إصدار طلبات مراقبة عبر MCP.

## MCP Gateway

بوابة الاتصال بين control plane والوكيل:

- تمرير أوامر مراقبة منظمة.
- تمرير سياق السيرفر وملفات المراقبة.
- تمرير تعريفات الوكلاء المتخصصين النشطة.
- تطبيق حدود الأدوات.
- استقبال النتائج.
- منع أي أداة غير مصرح بها.

## Agent Orchestrator

مسؤول عن تنسيق الوكلاء:

- تشغيل دورة المراقبة الدورية.
- إنشاء Server Sub-Agent لكل سيرفر ضمن دورة المراقبة.
- تحليل أولي لقيم المراقبة الشاملة.
- اختيار الوكلاء المتخصصين المطلوبين حسب الحاجة.
- دمج نتائج الوكلاء المتخصصين.
- استخدام RAG للاستعلام من الوثائق والتقارير.
- تحليل الحلول المقترحة.
- اختبار أو محاكاة الحلول في sandbox عند الإمكان.
- طلب قرار policy engine قبل أي تنفيذ.

## أنواع الوكلاء

```text
Agent Orchestrator
Server Sub-Agent
Specialist Agent
```

`Server Sub-Agent` ينشأ لكل سيرفر أثناء دورة المراقبة ويجمع القيم العامة.

`Specialist Agent` يعرف من لوحة الإدارة ويعمل عند الحاجة في مجال محدد، مثل القرص أو الشبكة أو Nginx أو قواعد البيانات.

## قاعدة التنفيذ

```text
كل تنفيذ ممنوع افتراضيا.
القراءة والتحليل مسموحان فقط ضمن أدوات read-only معتمدة.
```

## التخزين

- PostgreSQL للبيانات الأساسية.
- pgvector للفهرسة في MVP.
- Redis للqueues والمهام الدورية.
- Object storage أو مجلدات منظمة للتقارير والملفات المرفوعة.
