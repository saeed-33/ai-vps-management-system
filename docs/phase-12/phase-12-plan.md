# خطة المرحلة الثانية عشرة: أساس المراقبة الدورية وإنتاج التقارير

## الهدف

بناء أول قدرة عملية للوكيل: تشغيل دورة مراقبة دورية تنتج تقارير مراقبة دورية فقط، بدون تحليل مشكلات، بدون تشغيل وكلاء متخصصين، وبدون اقتراح أو تنفيذ حلول.

## النطاق

- إنشاء دورة مراقبة دورية يدوية عبر API.
- إنشاء Server Sub-Agent منطقي لكل سيرفر نشط.
- جمع قيم baseline read-only من fixture مؤقت.
- إنتاج تقرير مراقبة لكل سيرفر.
- توفير endpoints لعرض الدورات والتقارير.
- إضافة صفحة `/periodic-monitoring` في لوحة الإدارة.
- توثيق حدود المرحلة.

## خارج النطاق

- Scheduler تلقائي دائم.
- اتصال SSH أو جمع قياسات من سيرفر حقيقي.
- تحليل القيم أو تحديد وجود مشكلة.
- تشغيل الوكلاء المتخصصين.
- إيجاد حلول.
- sandbox execution.
- حفظ التقارير في PostgreSQL.

## endpoints المطلوبة

```text
POST /api/v1/periodic-monitoring/cycles
GET /api/v1/periodic-monitoring/cycles
GET /api/v1/periodic-monitoring/cycles/latest
GET /api/v1/periodic-monitoring/reports
```

## معيار النجاح

عند تشغيل دورة مراقبة، ينتج النظام:

- `cycle_id`.
- حالة الدورة.
- عدد السيرفرات المخطط فحصها.
- عدد السيرفرات التي تم فحصها.
- تقرير لكل سيرفر.
- قيم baseline منظمة.
- ملاحظة صريحة أن هذه المرحلة لا تحتوي تحليلا أو حلولا.
