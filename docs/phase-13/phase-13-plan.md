# خطة المرحلة الثالثة عشرة: جاهزية المراقبة الدورية المجدولة

## الهدف

إكمال نطاق المراقبة الدورية بحيث لا يقتصر على تشغيل يدوي، بل يدعم تشغيل scheduler داخل API لتكرار إنتاج تقارير مراقبة دورية.

## النطاق

- إضافة start/stop/status للـ scheduler.
- تشغيل دورة أولى مباشرة عند بدء الجدولة.
- تكرار تشغيل الدورة حسب `interval_seconds`.
- عرض حالة الجدولة في لوحة الإدارة.
- التحكم بالجدولة من صفحة `/periodic-monitoring`.
- توثيق طريقة الاستخدام والقيود.

## خارج النطاق

- Worker مستقل.
- تخزين دائم في PostgreSQL.
- اتصال فعلي بالسيرفرات.
- تحليل مشكلات.
- تشغيل وكلاء متخصصين.
- اقتراح أو تنفيذ حلول.

## endpoints المطلوبة

```text
POST /api/v1/periodic-monitoring/scheduler/start
POST /api/v1/periodic-monitoring/scheduler/stop
GET /api/v1/periodic-monitoring/scheduler/status
```

## معيار الجاهزية

يصبح النطاق جاهزا عندما يمكن:

- تشغيل دورة يدويا.
- تشغيل scheduler.
- رؤية حالة scheduler.
- إيقاف scheduler.
- رؤية التقارير الناتجة.
- إثبات أن الناتج لا يتجاوز تقارير مراقبة دورية فقط.
